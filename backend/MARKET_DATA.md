# Bitunix Market Data Service

## Назначение

Модуль `bitunix.py` обеспечивает получение публичных данных Bitunix, проверку структуры ответов и подготовку свечей к последующему анализу. API-ключи не используются. Сервис подключён к существующим адресам котировок и к новым адресам инструментов и свечей.

## Инструменты

`GET /api/market/instruments` возвращает инструменты из `trading_pairs`, для которых `quote = USDT` и `symbolStatus = OPEN`.

Результат содержит `symbol`, `base`, `quote` и `status`. Поле `isApiSupported` не используется для фильтрации: оно относится к исполнению сделок через API. Разделение криптовалютных и иных базовых активов не реализовано.

## Свечи

`GET /api/market/candles` принимает параметры:

| Параметр | Значение по умолчанию | Ограничения |
| --- | --- | --- |
| `symbol` | `BTCUSDT` | Активный инструмент в USDT |
| `interval` | `1m` | `1m`, `5m`, `15m`, `1h`, `4h` |
| `limit` | `5` | От 1 до 200 |
| `closed_only` | `true` | Исключение незавершённых свечей |

Свечи запрашиваются с типом `LAST_PRICE` и возвращаются по возрастанию времени. `limit` ограничивает исходный запрос к бирже; после фильтрации количество свечей может уменьшиться. Дополнительная загрузка истории до заданного количества не выполняется.

`open_time_ms` содержит начало интервала в миллисекундах Unix. `close_time_ms` соответствует началу следующего интервала. Цена закрытия и границы диапазона сохраняются из исходного ответа.

`is_closed` вычисляется сравнением конца интервала со временем компьютера на начало запроса свечей. Это оценка по локальным часам, а не подтверждение окончательности свечи со стороны биржи. Автоматическая синхронизация с часами Bitunix и проверка последующих пересмотров данных не реализованы.

## Единицы объёма

На проверенных ответах BTCUSDT и ETHUSDT выявлено различие между именованием полей объёма в `kline` и `tickers`:

| Источник | Поле биржи | Поле сервиса / смысл |
| --- | --- | --- |
| `kline` | `quoteVol` | `volume_base`: объём в базовой валюте |
| `kline` | `baseVol` | `volume_quote`: оборот в USDT |
| `tickers` | `quoteVol` | `volume_24h_usdt`: оборот за 24 часа в USDT |

Соответствие для свечей установлено по наблюдаемым данным. Отношение оборота к базовому объёму проверяется на попадание в диапазон `low–high` с допуском 0,1% от `high` на округление. Отрицательные, бесконечные и несогласованные нулевые объёмы отклоняются. Инструменты с множителями в символе требуют отдельной проверки единиц перед массовым сканированием.

## Проверка OHLC

Цены должны быть конечными и положительными; `close` должен находиться внутри `low–high`.

В исследованной выборке Bitunix обнаружены свечи, у которых `open` находится вне `low–high`, но точно совпадает с `close` предыдущей соседней свечи. Это рассматривается как наблюдаемая особенность данных, а не документированная гарантия биржи.

Такая свеча сохраняется только при наличии предшествующей проверенной свечи ровно за один интервал. Добавляется предупреждение `open_outside_range_matches_previous_close`. Значения OHLC не корректируются. Если совпадение подтвердить невозможно, свеча отклоняется.

Для будущих алгоритмов необходимо отдельно определять применимость таких свечей: предупреждение не означает пригодность для любого свечного паттерна. Для расчётов по времени требуется проверять непрерывность нужного окна. Соседние элементы массива при наличии пропусков не эквивалентны соседним временным интервалам.

## Качество ответа

| Поле | Назначение |
| --- | --- |
| `received_count` | Количество исходных записей биржи |
| `count` | Количество возвращённых свечей |
| `warning_count` | Количество возвращённых свечей с предупреждениями |
| `rejected_count` | Количество отклонённых исходных записей |
| `rejected_candles` | Время и причина отклонения |
| `gaps` | Внутренние пропуски между принятыми свечами |
| `data_quality` | Общая характеристика результата |

Значения `data_quality`: `ok` — проверка пройдена без предупреждений; `warning` — имеются предупреждения; `partial` — обнаружены отклонения или внутренние пропуски; `unavailable` — после обработки нет свечей. Значение `ok` не гарантирует свежесть, полноту запрошенного периода или окончательность данных.

Пропуски на краях выборки не определяются полем `gaps`. Полностью одинаковые дубликаты объединяются; противоречащие друг другу дубликаты одного времени вызывают ошибку всего запроса.

## Ошибки и нагрузка

- Неверные параметры API: HTTP 422.
- Неизвестный или неактивный инструмент: HTTP 404.
- Ошибка связи, ответ биржи с ошибкой или некорректная структура ответа: HTTP 502.
- Отдельные некорректные свечи: частичный ответ с перечислением отклонений.

Один запрос списка инструментов вызывает один запрос к бирже. Запрос свечей вызывает два: список инструментов для проверки символа и `kline`. Сетевой тайм-аут составляет 10 секунд на операцию. Общий кэш, повторные попытки, ограничитель частоты запросов и фоновый сбор данных не реализованы. Массовая загрузка свечей для всех инструментов требует отдельного планирования нагрузки.

## Проверенный объём

Автоматические тесты выполняются без сети. Живые ответы проверены для списка инструментов и выборок по 200 минутных свечей BTCUSDT и ETHUSDT. Остальные интервалы и инструменты не считаются проверенными этой процедурой.
