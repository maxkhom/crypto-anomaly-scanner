# Crypto Anomaly Scanner

Веб-приложение для мониторинга фьючерсного рынка Bitunix. Проект предусматривает обнаружение аномальных рыночных движений, описание условий формирования сигналов и статистическую оценку последующего изменения цены.

Текущая версия представляет собой локальный MVP с получением реальных котировок. Обнаружение аномалий, хранение истории сигналов и моделирование сделок не реализованы.

## Реализованные функции

- Получение публичных данных Bitunix без API-ключей.
- Список инструментов с котировкой в USDT и статусом `OPEN`.
- Цена последней сделки, изменение цены и объём за 24 часа.
- Поиск по символу, сортировка по колонкам и ручное обновление.
- Тёмный интерфейс и горизонтальная прокрутка таблицы на узком экране.
- Время получения данных, обработка ошибок и список недоступных котировок.

Количество инструментов определяется текущим ответом биржи. Фильтр включает все фьючерсные инструменты в USDT со статусом `OPEN`. Разделение криптовалют и других базовых активов не реализовано.

## Архитектура

```text
Браузер: React + TypeScript
           ↓ /api/market/tickers
Vite: перенаправление /api на локальный backend
           ↓
FastAPI + Python: получение данных и расчёты
           ↓
Публичный REST API Bitunix
```

```text
backend/
  main.py             # API и проверка состояния
  market.py           # Список инструментов, котировки и расчёты
  bitunix.py          # Общий сервис Bitunix и проверка свечей
  tests/              # Автоматические проверки без сетевых запросов
  requirements.txt    # Библиотеки Python
frontend/
  src/App.tsx         # Таблица, поиск, сортировка и загрузка
  src/App.css         # Стили экрана
  src/index.css       # Общие стили
  vite.config.ts      # Подключение локального backend
README.md
.gitignore
```

## Требования

Проект проверен на macOS с Apple Silicon, Python 3.13 и Node.js 24. Дополнительно требуются npm, Git и сетевой доступ к `fapi.bitunix.com`.

Python-библиотеки устанавливаются в отдельное виртуальное окружение. Их версии в `requirements.txt` не закреплены; версии frontend-зависимостей сохранены в `package-lock.json`.

## Установка

Для получения локальной копии проекта требуется открыть Terminal в каталоге, предназначенном для хранения исходного кода, и выполнить команды:

```bash
git clone https://github.com/maxkhom/crypto-anomaly-scanner.git
cd crypto-anomaly-scanner
```

При наличии локальной копии повторное клонирование не требуется. Дальнейшие действия выполняются в существующем каталоге проекта.

### Backend

Для установки зависимостей и запуска backend требуется выполнить команды из корневого каталога проекта:

```bash
cd backend
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn main:app --reload
```

Процесс backend должен оставаться запущенным в текущей вкладке Terminal. Адрес проверки состояния: [http://127.0.0.1:8000/api/health](http://127.0.0.1:8000/api/health).

### Frontend

Для запуска frontend требуется открыть отдельную вкладку Terminal, перейти в корневой каталог проекта и выполнить команды:

```bash
cd frontend
npm ci
npm run dev
```

Интерфейс доступен по адресу, указанному в выводе Vite; по умолчанию — [http://localhost:5173/](http://localhost:5173/). Для загрузки котировок требуется работающий backend.

### Повторный запуск

Если состав зависимостей не изменялся, их повторная установка не требуется.

Запуск backend выполняется из каталога `backend`:

```bash
source .venv/bin/activate
python -m uvicorn main:app --reload
```

Запуск frontend выполняется в отдельной вкладке Terminal из каталога `frontend`:

```bash
npm run dev
```

Для остановки сервера используется сочетание клавиш `Control + C` в соответствующей вкладке Terminal.

## API

| Адрес | Назначение |
| --- | --- |
| `/api/health` | Работа backend; доступность биржи не проверяется |
| `/api/market/ticker` | Одна котировка BTCUSDT |
| `/api/market/tickers` | Список котировок для таблицы |
| `/api/market/instruments` | Активные фьючерсные инструменты в USDT |

Адреса доступны на `http://127.0.0.1:8000` при запущенном backend.

## Расчёты и обновления

Цена определяется полем `lastPrice`, начальная цена 24-часового окна — полем `open`, объём в валюте котировки — полем `quoteVol`.

```text
Изменение за 24 часа (%) = (lastPrice / open − 1) × 100
```

Backend использует `Decimal` для расчёта. Цена и объём передаются строками для сохранения десятичной записи; процент возвращается числом с округлением до четырёх знаков. В таблице процент показан с двумя знаками, объём — с округлением до целых USDT.

Каждая загрузка списка вызывает два запроса к Bitunix: `trading_pairs` и `tickers`. Индивидуальные запросы котировок для каждого инструмента не выполняются. По умолчанию применяется сортировка по убыванию объёма в USDT.

Котировки, не прошедшие проверку корректности, исключаются из таблицы; их символы перечисляются в `unavailable_symbols`. Поля `eligible_count` и `count` содержат соответственно число подходящих инструментов и число котировок, прошедших проверку. Поле `fetched_at` содержит время завершения получения данных на backend в UTC. Время последней сделки на бирже этим полем не определяется.

Данные загружаются при открытии страницы и по кнопке «Обновить». Фоновое сканирование, общий кэш и хранение истории не реализованы. Каждый подключённый клиент инициирует отдельные запросы. При ошибке обновления интерфейс сохраняет ранее полученные данные и отображает предупреждение.

## Проверки

Для проверки frontend требуется выполнить команды из каталога `frontend`:

```bash
npm run build
npm run lint
```

Первая команда проверяет TypeScript и создаёт сборку в `frontend/dist`; вторая проверяет код линтером.

Для проверки сервиса Bitunix требуется выполнить команду из каталога `backend`:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Набор содержит 19 тестов на встроенном модуле `unittest`; подключение к бирже не требуется. Проверяются фильтрация инструментов, порядок и завершённость свечей, объёмы, пропуски, отклонение некорректных данных и обработка сетевых ошибок. Pytest в текущей версии не подключён.

Ручная проверка включает загрузку котировок в интерфейсе, поиск BTCUSDT, сортировку таблицы и обновление данных. Правила работы со свечами описаны в [документации сервиса](backend/MARKET_DATA.md).

## Настройки и публикация

В текущей версии переменные окружения и API-ключи не требуются. Адрес Bitunix задан в Python, локальный адрес backend — в `frontend/vite.config.ts`.

Файлы `.env`, виртуальное окружение, `node_modules` и результаты сборки исключены через `.gitignore`.

Исходный код опубликован на GitHub. Развёртывание публичного приложения, конфигурация production-окружения, HTTPS и поддержка PWA не выполнены. Прокси Vite используется локальным сервером разработки. Для развёртывания требуется отдельно разместить Python backend и настроить адрес API либо обратный прокси. Каталог `dist` содержит только сборку frontend.

## План развития

- Изменение цены за 1m, 5m, 15m, 1h и 4h; ускорение движения.
- Relative volume, funding, RSI и волатильность; проверка доступности рыночного OI Bitunix.
- Объяснимый Anomaly Score, уровни и потенциальные сетапы.
- История сигналов, проверка последующего движения и аналитика.
- Backtesting и paper trading с комиссиями и проскальзыванием.
- Оптимизация запросов, realtime, публикация и PWA для iPhone.

## Ограничения

Приложение предназначено для исследования рыночных данных. Показатель изменения цены не является рекомендацией к совершению сделки. Планируемый Anomaly Score предназначен для оценки аномальности рыночного состояния и не интерпретируется как вероятность получения прибыли. Исполнение реальных сделок не реализовано. Торговля фьючерсами связана с риском потери средств.
